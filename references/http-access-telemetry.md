# Optional HTTP transport-admission diagnostics

Use this only when the user requests access diagnostics sent to their explicitly selected telemetry receiver. Add `"httpAccessDecisions": true` to the protected startup [telemetry configuration](telemetry.md). It defaults to false, independently of `httpRequests`, `httpConnections`, grant observations and trace sampling. No desktop, Jarness, Docker, Collector launch or server is needed by the SDK; actual observations occur only at the owned HTTP(S) server boundaries below. Configuration never authorizes requests or deployment.

The SQLite/PostgreSQL management, scoped preview and exact-release hosts share these hooks. `capabilities.workflowRuntime.httpAccessTelemetry` (or `httpAccessTelemetry` for exact-release discovery) describes support, not whether that owner enabled it. Older strict runtimes may refuse this new startup option; use matching runtime bytes.

| Fixed stage | Entered predicate |
| --- | --- |
| `headers` | Header ambiguity, proxy, Host/peer, Origin/Fetch Metadata, path shape and readiness guards, in their original order |
| `owner-key` | Actual owner bearer comparison |
| `preview-session` | Actual scoped session authentication, including expiry/revocation |
| `local-bootstrap` | Opted-in local-machine bootstrap's extra CSRF/no-owner-key/required-instance guards |
| `grant-token-syntax` | Delegated token **syntax only**; lookup, role, target, expiry/revocation and action authority remain separately enforced |
| `instance` | Applicable required-instance and mismatch guards; an optional absent instance on an ordinary route can be admitted |
| `protocol` | Protocol pin check; capability discovery deliberately precedes this predicate |
| `release-pin` | Exact-release async-read pin or delegated trusted-context release comparison |
| `signed-webhook` | Signature-header shape, bounded body reading and actual signature/input verification, before message admission |
| `local-rate-requests`, `local-rate-controls` | Selected instance-local token-bucket admission, including the post-debit drain guard |
| `coordinated-rate-requests`, `coordinated-rate-controls` | Selected trusted coordinator's bounded debit/receipt wait, including the post-debit drain guard |

Only reached predicates are observed, once per entered boundary. An earlier refusal prevents later observations. Public preview HTML passes header checks but does not test an owner key; disabled/unknown routes can still reach normal owner-key checks. Stream reads can perform multiple delegated release comparisons. These are evaluation counts, not unique requests, unique callers, business decisions or successful operations.

Each ended predicate emits `jevable.http.access` (internal span) and `jevable.http.access.ended` (correlated structured log), using the configured destinations. Each is an independent root: no request `traceparent`, baggage, saved execution identity or ambient context is adopted before authentication. They do not alter HTTP-to-workflow parentage, outgoing headers or retained traces. No raw header/path/peer, token/digest/signature, workflow/coordinator identity, actor, body, payload or error text is included. Resource identity remains separately reviewed diagnostic metadata.

With **both** `httpAccessDecisions` and `httpRequests`, the HTTP server observation links to its one quota span. Its ended span/log also carries that observation's `jevable.http.rate.trace_id`, `.span_id` and `.sampled`, so configured logs can join the two even with unsampled or logs-only operation. These are ephemeral diagnostic IDs, not debit request UUIDs or workflow IDs. Only the owned quota observer supplies them; incoming headers/baggage never supply this link. Linking does not construct the HTTP span early or bypass authenticated incoming-parent validation. Refused/read HTTP requests remain independently rooted; admitted operations retain normal HTTP-to-workflow ancestry. At most one detached validated quota context is retained per request; these IDs never enter metric labels or response headers. No request instrumentation means independent quota observations without a request join.

Outcomes are `admitted` (that predicate returned), `refused` (its expected transport rejection) and `failed` (unexpected predicate fault). Admission is **not** granted workflow authority or proof of a commit/client receipt. A well-formed unissued/revoked grant may pass `grant-token-syntax` and still be denied by the runtime. Expected refusals use INFO/unset span status; faults use ERROR and fixed `error.type: http_access_failed`, never original error details. Logs add measured `jevable.duration.seconds`.

For quotas, only a canonical local exhaustion or **validated** coordinator denial is `refused`. Coordinator exceptions, invalid/mismatched receipts, timeout, or drain before dispatch are `failed`; a debit may already have committed. HTTP 503 is not proof of rollback, permission to retry or authority to refund. `admitted` means the selected quota gate and readiness guard returned—not command/grant authorization, workflow dispatch, acknowledged storage or business completion. Credential-free HTML/capabilities and failures before quota entry emit no quota evaluation. Each reached debit is still called once, without diagnostic-driven retry, fallback or refund.

With `metricsEndpoint`, `jevable.http.access.evaluations` is a cumulative monotonic `{evaluation}` counter and `jevable.http.access.duration` is a cumulative seconds histogram. The only point labels are `jevable.http.access.stage` and `jevable.http.access.outcome`: thirteen fixed stages × three outcomes, at most 39 groups. Standard runtime duration buckets apply. Timing covers only the entered predicate; signed-webhook admission includes its bounded body wait, and coordinated quota admission includes its wait/receipt validation/drain check, not just local CPU time. It does not measure a database's internal SQL/COMMIT phases. Metrics/logs remain present when trace sampling is zero; destinations still independently control exported signal types. Series reset under a new owner resource instance; never add successive cumulative snapshots as events.

Observation failure cannot replace original predicate values/errors, repeat checks, grant access, replay execution or trigger a retry. Collector loss drops diagnostics under existing bounded transport behavior, never changes credentials or workflow authority. A shutdown or reopened owner does not reconstruct past evaluations. These best-effort observations are not a durable access/security audit or request census. Parser/TLS failures before handlers, the separate preview gateway, body/operation-schema validation outside webhook admission, coordinator-internal SQL/commit certainty and complete delegated grant admission are not included; use other existing diagnostics and retained authorization evidence where applicable. Full API/access/journal and deployed Collector/backend qualification remain open.

Source tests exercise real private SQLite/server/loopback protobuf export, with serializer-side semantic capture for the original stages. Quota tests independently decode **received** protobuf spans/links/logs/counters/duration distributions for local and explicitly labelled in-process coordinated adapters, including unsampled and individual-signal modes, refusals, deadlines, late receipts, drain and adversarial diagnostic hooks. These are not a real PostgreSQL quota-backend, browser, arbitrary artifact/container/cluster, production security or backend-retention qualification. Consult the receipt for the exact installed/extracted/runtime bytes and scenarios evaluated; older image receipts do not qualify changed bundles.
